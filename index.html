How it works

1. Three colours are the digits. = 0, = 1, = 2. One cell holds one trit, a ternary digit, the three-state cousin of the bit. A trit carries log₂3 ≈ 1.58 bits, and base 3 is the closest whole number to e ≈ 2.718, the theoretically most economical base.

2. Short codes for frequent letters. A character is 1 to 4 colour cells long. The most common letters get the shortest codes, as in Morse code and Huffman coding (the idea behind ZIP files and LLM tokenizers). E, T and A in English (О, Е, А in Russian) need a single cell.

3. White and black close every character. After its colour cells, each character ends with a marker: white = end of a letter, black = end of a word, so no space is needed. Because characters vary in length, this end signal is what keeps the reader in sync, just like the start and stop bits on a serial cable or the prefixes in UTF-8.

4. Empty cells carry no meaning. A marker that follows another marker (or opens the grid) is a filler and is skipped. That lets any text fill a perfect square: side = √(cells), rounded up, with the spare white cells spread evenly between characters.

5. Read like a book. Row by row, left to right, from the top-left corner.

Where the ideas come from

Nothing here is new on its own. Each rule borrows one idea that already runs the digital world, which is what makes the code a good teaching tool.

How close to Huffman is it? Weighted by how often each letter appears in English, a letter takes 1.89 colour cells on average, instead of 3 in a fixed-length ternary code. Shannon's limit for a ternary code with no separators is about 2.63 cells per English letter. Mondrian Code goes below that on colour cells only because it adds a white or black marker to every character (2.89 cells in total). That is the deliberate trade-off: a true Huffman code is prefix-free, so it needs no separators, but it is hard to read by eye and one misread cell can scramble everything after it. Mondrian Code pays one marker per character for readability and recovery. Against a fixed 3-cell code plus marker (4 cells), text is about 28% shorter.

Compared with the bit system

What the numbers say. Mondrian Code needs the fewest squares of any code here that a person can read by eye: 2.89 per letter, against 4.20 bits for the best binary Huffman code (31% fewer) and 8 for ASCII (64% fewer). That is the advantage of three colours over two. But each square can show 5 states, and the white and black markers use part of that capacity, so in pure information terms it is about 62% efficient, where Huffman codes reach 97–99%. The markers are what you pay for being able to see where every letter ends and to recover after a misread cell. In real text the gap narrows: about one character in six is a space, which binary codes must store and Mondrian Code gets free inside the black marker.

The alphabet

Two scripts: Latin (letter order by English frequency, plus the special letters of German, Swiss German, French, Spanish, Portuguese and the Nordic languages) and Cyrillic (order by Russian frequency, plus Ukrainian, Belarusian, Serbian and Macedonian letters). The same colours mean different letters in the two scripts, so the reader needs to know which one. Digits and punctuation are shared.

What it is good for

Signature and art: a name, a date or a motto hidden in a logo, a poster or a print. Teaching: encode your own name and you have learned bits, bytes, variable-length codes, error checking and why an LLM turns words into tokens, in ten minutes. Puzzles: decode-the-poster challenges.

What it is not: encryption (anyone can break it by counting colours) or data storage (a QR code does that far better, with error correction).
